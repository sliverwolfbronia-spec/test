# 考研倒计时小组件 · 开发 Prompt

这个仓库存放一段给本地 AI Agent（Claude Code、Cursor、Codex 等）用的开发指令，让它在小米 / Redmi K80 至尊版（K80U）上开发一个考研倒计时 App 和桌面小组件。

## 怎么用

1. 电脑装好 Android Studio（自带 Android SDK 和 JDK 17）。
2. 手机打开开发者选项：设置 → 我的设备 → 全部参数与信息 → 连点「OS 版本」7 次。
3. 在开发者选项里打开「USB 调试」「USB 安装」「USB 调试（安全设置）」。最后一项要求插 SIM 卡并登录小米账号。
4. 用数据线连接电脑，执行 `adb devices`，确认能看到设备。
5. 新建一个空文件夹，在里面启动本地 Agent，把下面「Prompt」一节的全部内容粘贴给它。

## 先说清楚一个限制

Android 桌面小组件由桌面（launcher）进程绘制，App 不能每 0.1 秒刷新一次，否则会被系统限流，还很耗电。所以 Prompt 里的方案分三层：

| 显示位置 | 跳动精度 | 说明 |
|---|---|---|
| 桌面小组件 | 1 秒 | 用系统 `Chronometer` 控件在桌面进程里走秒，几乎不耗电 |
| App 全屏页 | 0.1 秒 | 打开 App 就是一个持续跳动的大号倒计时 |
| 悬浮窗 / 动态壁纸（可选） | 0.1 秒 | 想在桌面上也看到 0.1 秒跳动，就用这两种 |

## Prompt

````markdown
# 角色与任务

你是一名资深 Android 工程师。请在当前空目录里，从零开发一个原生 Android App：「考研倒计时」。它由三部分组成：全屏倒计时页、桌面小组件，以及可选的 0.1 秒高频显示模式。目标设备是我的 Redmi K80 至尊版（K80U），系统是小米 HyperOS（基于 Android 15 或 16）。我是考研学生，不太懂 Android 开发，所以每一步都要由你自己完成、自己验证。

# 背景

我在备考，时间观念差。我想在手机上一直看到「离考试还剩多少分钟」，而且数字要持续跳动，制造紧迫感。

# 功能需求

## 1. 目标时间
- 可以自由设定目标日期和时间，精确到分钟。默认值：2026-12-19 00:00，时区 Asia/Shanghai。
- 可以给目标起名字（默认「考研初试」），显示在倒计时上方。
- 设置保存在本地（DataStore），重启手机后仍然有效。
- 进阶（可选）：支持保存多个目标，小组件可以各自选择显示哪一个。

## 2. 倒计时格式
- 以「分钟」为主单位，不进位到小时和天。
- 默认格式：`104,563 分 27.4 秒`。分钟数带千分位，秒数固定两位整数加一位小数。
- 备选格式（设置里切换）：纯小数分钟 `104,563.457 分`，保留三位小数（0.001 分 = 0.06 秒，满足 0.1 秒精度）。
- 时间过了目标点：显示「已到达」，或改为正计时 `+12 分 03.5 秒`，设置里可选。

## 3. 全屏倒计时页（App 主界面）
- 打开 App 直接显示大号倒计时，每 0.1 秒刷新一次（用 Compose 的 `withFrameNanos` 或 `LaunchedEffect` 循环，按 100ms 节拍取整）。
- 数字用等宽字体（`FontFamily.Monospace` 或 `fontFeatureSettings = "tnum"`），跳动时宽度不变，文字不左右抖。
- 深色背景、高对比。页面打开时可以选择保持屏幕常亮（设置开关）。
- 右上角入口进入设置页。

## 4. 桌面小组件（AppWidget）
- 用传统 `AppWidgetProvider` + XML `RemoteViews` 实现。不要用 Jetpack Glance，Glance 不支持 `Chronometer`。
- 显示：目标名 + 剩余分钟数 + 当前分钟内剩余秒数，秒数每秒跳动。
- 实现方式：
  - 秒数用 `Chronometer`（`setCountDown(true)`，API 24+），它在桌面进程里自己走秒，App 不用唤醒。
  - 分钟数在每个整分钟边界更新一次：用 `AlarmManager.setExactAndAllowWhileIdle` 安排下一次更新；如果拿不到精确闹钟权限，就退回 `setWindow`，并在设置页提示我授权。
  - `Chronometer` 会显示成 `00:59` 这样带分钟前缀的格式。请想办法只露出秒数部分，比如用固定宽度容器加右对齐加裁剪，或者其他可靠办法。在真机上截图验证效果。
- 至少提供 2 个尺寸（如 4×1 和 2×2），支持调整大小。
- 点击小组件打开全屏倒计时页。
- 监听 `ACTION_TIME_CHANGED`、`ACTION_TIMEZONE_CHANGED`、`ACTION_BOOT_COMPLETED`、`ACTION_MY_PACKAGE_REPLACED`，收到后立即刷新所有小组件。
- 不要声称小组件能 0.1 秒跳动，它做不到。

## 5. 0.1 秒高频模式（第二阶段，可选）
做完前 4 项并验证通过后，再实现下面两种模式，设置里各有开关，默认关闭：

- **悬浮窗模式**：前台服务 + `SYSTEM_ALERT_WINDOW` 悬浮窗，在任何界面都显示 0.1 秒跳动的倒计时。可以拖动、调透明度、调大小，长按关闭。熄屏时暂停刷新，亮屏后恢复。
- **动态壁纸模式**：`WallpaperService` 在桌面背景上绘制倒计时，只在壁纸可见时以 10fps 绘制，不可见时停止。可以选择背景色和字号。

## 6. 时间计算正确性
- 剩余时间统一由 `目标时刻的 epoch 毫秒 - System.currentTimeMillis()` 算出，每帧重新计算，不累加计时器。这样不会漂移，系统改时间后也能自动校正。
- 目标时间用 `ZonedDateTime` 加用户选择的时区，转成 `Instant` 存储。
- 计算和格式化逻辑写成纯 Kotlin 函数，放在单独文件里，并写 JUnit 单元测试，至少覆盖：
  - 正常剩余时间（多个样例，手算核对）
  - 剩余不足 1 分钟、不足 1 秒
  - 恰好到达、已经过去
  - 千分位格式、小数位四舍五入还是截断（统一用截断，避免显示 60.0 秒）
  - 跨夏令时的时区（如 America/New_York），保证不出错

# 技术栈
- Kotlin，Jetpack Compose（Material 3）做 App 界面。
- minSdk 26，targetSdk 和 compileSdk 用本机已安装的最新稳定版（35 或 36）。
- Gradle Kotlin DSL + version catalog（`libs.versions.toml`）。
- 包名：`com.kaoyan.countdown`（可改）。
- 不接入任何网络、统计或广告 SDK，不申请用不到的权限。

# HyperOS 适配（必须处理）
HyperOS 后台管控很严。请在 App 设置页做一个「保活检查」区域，逐项显示状态，并提供跳转按钮：
- 精确闹钟权限（Android 12+：`canScheduleExactAlarms()`）
- 悬浮窗权限（仅悬浮窗模式需要）
- 通知权限（Android 13+，前台服务需要）
- 电池优化：引导我在「省电策略」里选「无限制」
- 自启动：引导我打开小米的「自启动」开关。跳转小米专有页面时用 try/catch 包住，失败就退回系统应用详情页。

把每一项在 HyperOS 里的手动设置路径用中文写进项目 README。

# 工作流程
1. **环境检查**：确认 JDK、Android SDK、adb 可用，`adb devices` 能看到手机。用 `adb shell getprop ro.build.version.sdk` 和 `adb shell getprop ro.mi.os.version.name` 查出 Android API 版本和 HyperOS 版本，告诉我结果。缺什么就告诉我怎么装，不要瞎猜。
2. **先问我**：开工前用一条消息问我下面几件事，每项都给默认值，我回「默认」就全用默认：
   - 目标时间和名称
   - 倒计时格式（默认：分 + 秒带一位小数）
   - 配色（默认：黑底白字，最后一分钟变红）
   - 第二阶段做悬浮窗、动态壁纸、两个都做，还是都不做
3. **第一阶段**：完成第 1～4 项和第 6 项。跑单元测试，`./gradlew assembleDebug`，`adb install -r` 装到手机。
4. **真机验证**：
   - 用 `adb shell screencap` 截图并查看，确认全屏页和小组件显示正确、数字不抖、秒数在跳。
   - 隔一分钟再截一次图，确认小组件分钟数自动减少了。
   - 用 `adb shell cmd alarm` 或 `dumpsys alarm` 确认闹钟已正确注册。
   - 把截图发给我看。
5. **第二阶段**：按我在第 2 步的选择实现第 5 项，再做一轮真机验证。悬浮窗模式运行 10 分钟后，用 `dumpsys batterystats` 或 `top` 粗略检查 CPU 占用，告诉我耗电情况。
6. **收尾**：
   - 生成 release APK。用新建的本地 keystore 签名，keystore 和密码不提交进 git，写进 `.gitignore`。
   - 在项目根目录写 README：功能、安装方法、HyperOS 设置步骤、已知限制。
   - `git init` 并按阶段提交。

# 质量要求
- 每完成一个阶段都要实际编译、安装、截图验证，不要只写代码不运行。
- 遇到做不到的需求（比如小组件 0.1 秒刷新），直接告诉我原因和替代方案，不要假装做到。
- 代码清晰、有必要的注释，不堆砌无用抽象。
- 出错时先读完整报错，定位原因再改，不要盲目重试。
- 最后给我一份简短报告：做了什么、怎么用、哪些地方需要我在手机上手动设置、已知问题。
````
